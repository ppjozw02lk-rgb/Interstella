## กฎคัดเข้าคลัง: ทุกแนว ยกเว้น furry

ผู้ใช้สั่ง **“เอาทุกแนวมาเลย ไม่ต้องค้น”** → ยกเลิกกฎเดิมที่บังคับว่าต้องมีคำว่า “femboy”
ตอนนี้ตัวกรองชั้นสุดท้ายคือ `isAllowed()` ใน [sources.js](assets/js/sources.js) ซึ่งเหลือแค่:

```js
const isAllowed = (d) => !isFurry(d);   // รับทุกแนว ตัดแนวสัตว์อย่างเดียว
```

> `isFemboy()` ยังอยู่ในโค้ด (ใช้อ้างอิง/เทสต์ได้) แต่ **ไม่ใช่เงื่อนไขในการเข้าคลังอีกต่อไป**
> `EXTRA_BY_SOURCE` ก็ยังอยู่ แต่เป็นแค่ป้ายบอกที่มา ไม่ใช่กุญแจ

### ไม่ต้องค้น — ไล่เอาทุกอย่างที่เจอ

หน้าแรกไม่ยิงคำค้นใด ๆ แต่ให้แต่ละแหล่งไล่หน้าล่าสุดของตัวเอง แล้วค่อยไล่หน้า 1..N ต่อแบบเบื้องหลัง

| แหล่ง | หน้าแรก (ไม่ต้องค้น) | ไล่ต่อ |
|---|---|---|
| miku-doujin.com | หน้าแรกเว็บ (งานล่าสุด) | `?page=N` ถึง 60 หน้า |
| doujin-th.com | board หน้า 1–3 (72 การ์ด) | `board,1.{offset}.html` ถึง ~1,960 หน้า |
| netoruhentai.com | `/doujinshi` หน้า 1 | `/doujinshi?page=N` ถึง ~1,705 หน้า |
| neko-hentai.net | ⚠️ ยังดึงไม่ได้ (Cloudflare 403) | — |

การไล่ทำงาน**ต่อเนื่องอัตโนมัติ**จนกว่าจะครบทุกแหล่งหรือผู้ใช้กด “หยุด”
ตำแหน่งที่ไล่ถึงแล้วถูกเก็บใน `localStorage` (`femboy-vault:scan`) จึงปิดเว็บแล้วกลับมาไล่ต่อจากเดิม

> ⚠️ **ข้อจำกัดเวลาและโควตา:** proxy จำกัด 40 req/นาที/แหล่ง และ netoruhentai ต้องดึงหน้า detail
> ทีกลายเพื่อเอาชื่อต้นฉบับ (การ์ดบนเว็บมีแต่ชื่อไทย) → ไล่คลังใหญ่สุดจึงใช้เวลาเป็นชั่วโมง
> ปุ่ม “หยุด” ใช้ได้ตลอด คลังที่เก็บแล้วไม่หาย

ผู้ใช้สั่ง “เอาแนว furry ออก” → `isFurry()` ใน [assets/js/sources.js](assets/js/sources.js)

### ไม่มีข้อมูลตัวอย่างแล้ว

[data.js](assets/js/data.js) เหลือแค่ค่าคงที่ (`FACETS`, `TAG_COLORS`, `LANG_LABEL`, `SORT_OPTIONS`)
**ไม่มีคลังเดโมอีกแล้ว** — เคยมี `LIBRARY` สมมติ 16 รายการ (มีแนว furry ปนอยู่ด้วย) ที่ไม่มีใครอ่าน
เพราะ [app.js](assets/js/app.js) ดึงข้อมูลจากต้นทางจริงอย่างเดียว ถ้าต้นทางล้ม เว็บจะบอกตรง ๆ ว่าดึงไม่ได้
แทนที่จะโชว์ข้อมูลปลอม

### doujin-th.com — สิ่งที่ต้องรู้

เว็บนี้เป็น **ฟอรัม Invision** ไม่ใช่เว็บอ่านดับจินตรง ๆ มีจุดที่ทำให้พลาดง่าย:

**1. เลขกลางใน URL คือ “จำนวนรายการที่ข้าม” ไม่ใช่เลขหน้า**

| URL | ได้หน้า |
|---|---|
| `board,1.0.html` | หน้า 1 |
| `board,1.23.html` | หน้า 1 (เหมือนกันเป๊ะ) |
| `board,1.24.html` | หน้า 2 |
| `board,1.48.html` | หน้า 3 |

สูตรที่ถูกคือ **offset = (หน้า − 1) × 24** มีเทสต์กันผิดพลาดนี้อยู่ใน [check-parsers.js](check-parsers.js)
ขนาดจริง: 24 การ์ด/หน้า, หน้าสุดท้ายที่ offset 47,016 มี 12 การ์ด → **1,960 หน้า ≈ 47,028 รายการ**

**2. เว็บไม่มีช่องค้นหาของตัวเอง** — ช่องในหน้าเว็บคือ Google CSE ฝัง
(`<form action="https://www.google.com">` + hidden `cx=003772632849311655372:-igy6k3yaqk`)
ส่วน Invision Search ปิดสำหรับผู้มาชม (`action=Search` คืนหน้า Index เปล่า)
→ จึงใช้ **การไล่หน้า** แทนการค้น และใช้หน้าแท็กของเว็บเองเป็นทางลัด

**3. หน้าแท็กของเว็บใช้ได้จริง** — `index.php?action=tags&tagid=N`
ตัวอย่างที่ใช้ในโค้ด: `tagid=3309` = “femboy friend” → ได้ 2 รายการทันทีโดยไม่ต้องไล่คลัง
(หน้า tag cloud มีแค่ top 50 แท็ก ไม่มีการแบ่งหน้า จึงค้นหาแท็กอื่นจากที่นี่ไม่ได้)

**4. ปกไม่ได้อยู่ใน `<img>`** — อยู่ใน `<style>` ก่อนการ์ดทุกใบ

```html
<style>#post_doujin_2 { background-image:url('https://s1.hentaithai.net/image/2022/...-001.jpg'); }</style>
<a href="//doujin-th.com/forum/index.php?topic=35154.0" class="..." title="ชื่อเรื่อง">
```

โค้ดไล่เอกสารด้วย regex เดียวเพื่อให้ปกยังผูกกับการ์ดที่ถูกต้องเสมอ

**5. วันที่มาจาก path ของรูป** — `/image/2022/2022-09-18/...` หรือ `/thai/2026/2026-09-30/04865/1.webp`
หน้า listing ไม่บอกวันที่เลย การเดาวันที่จาก “x เดือนที่แล้ว” จึงไม่ทำ — ใช้วันที่ใน path ตรง ๆ

**6. หน้า thread มีรูปของดับจินอื่นปนอยู่ท้ายหน้า** (ส่วน “เรื่องคุณอาจสนใจ”)
ถ้าดูดึงจากทั้งเอกสารจะได้รูปของเรื่องอื่นมาปน → โค้ดใช้ `og:image` เป็นตัวอ้างอิง
แล้วเก็บเฉพาะ URL ที่อยู่ในกลุ่มเดียวกัน จึงได้เฉพาะรูปของเรื่องนี้ (เรียงตามเลข 1..N)

### neko-hentai.net — ⚠️ ถูก Cloudflare บล็อก (ทดสอบจริงทุกทาง)

| วิธีดึง | ผล |
|---|---|
| `curl` + UA/header เต็มแบบ Chrome | **403** |
| Node `https` / `fetch` | **403** |
| Chrome headless (`--dump-dom`) | **403** หน้า “Just a moment...” |
| `api.allorigins.win` | **520 / 522** |
| `api.codetabs.com` | **522** |
| `corsproxy.io` | **401** |
| `fetch()` จากเบราว์เซอร์ (ผ่าน CORS) | **Failed to fetch** — เว็บไม่ได้ส่ง CORS |
| เบราว์เซอร์จริงของคนใช้ | ✅ **ผ่าน** |

สรุป: **เว็บนี้ใช้งานได้เฉพาะเบราว์เซอร์จริงของคนใช้** แต่พอผ่านแล้วก็อ่านข้ามโดเมนไม่ได้
เว็บนี้จึงยัง **ดึงข้อมูลผ่านเว็บเราไม่ได้** — โค้ด adapter เขียนเสร็จและทดสอบ parser ผ่านแล้ว
(ด้วย HTML จริงที่บันทึกไว้ใน `.tmp-neko-*-fixture.html`) แต่ตอนรันจริงจะขึ้นข้อความว่าถูกบล็อก
**ไม่แต่งข้อมูลปลอม** เหมือนกันทุกแหล่ง

สิ่งที่ค้นได้จริงตอนทดสอบในเบราว์เซอร์:

- `POST /controller/search.php` body `keysearch=femboy` → **3 รายการ**
  (`keysearch=สาวดุ้น` คือหมวดที่ผู้ใช้อนุมัติให้ผสม)
- **GET ที่ URL เดียวกันไม่กรอง** — ต้องเป็น POST เท่านั้น (ยืนยันแล้ว: GET คืนหน้าแรก 1,000 ลิงก์)
- การ์ด: `<a href="https://neko-hentai.net/{slug}/" title="...">` + `<div class="poster" style="background-image:url(.../uploads/thumbnail/{hash}.jpg)">`
  slug มีทั้งแบบไม่มีขีด (`lb3xv`) และมีขีด (`ehohinya-ehohin-watashi-no-kano`) → regex รองรับทั้งสองแบบ
- หน้าเรื่อง: รูปเป็น `<img data-src=".../uploads/upload-images/{ts}/NNNN.jpg">` (lazy-load ต้องอ่าน `data-src`)
- รูปในหน้าเรื่องเริ่มที่หน้า 9 (0009.jpg) — หน้า 1–8 ไม่อยู่ใน DOM ตอนโหลดครั้งแรก
  ตัวเลขจำนวนหน้าที่แท้จริงจึงยังยืนยันไม่ได้จาก HTML ที่ดึงได้

### หมายเหตุเรื่อง search ของ miku-doujin

`GET /?s=<คำค้น>` **ไม่ใช่ช่องค้นหาจริง** — ทดสอบแล้วว่าคืนหน้าแรกกลับมาเหมือนกันทุกคำค้น
(แม้แต่คำมั่ว `zzzxyznotfound999` ก็ยังได้ 22 รายการ)

ช่องค้นหาจริงเป็น **AJAX POST**:

```
POST https://miku-doujin.com/controller/search/general/
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: https://miku-doujin.com/

keysearch=<คำค้น>
```

ผลลัพธ์เป็น HTML ชิ้นเดียว (การ์ดละ 1 `<a class="inz-a">`)
proxy จึงรับพารามิเตอร์ `post=` ใน `/api/proxy` เพื่อส่งต่อ POST ให้

### หน้า detail ของ miku-doujin

- รูปทุกหน้าอยู่ใน `<div id="manga-content">` เป็น `<img class="lazy" data-src="...">`
  — ใช้ `data-src` ไม่ใช่ `src` และนามสกุลไม่คงที่ (`.webp` หรือ `.jpg`)
- ฟิลด์ metadata อยู่ในรูป `<p><small>ป้าย : <a class="badge ...">ค่า</a></small></p>`
- ช่อง `เรื่อง` บางเล่มเป็นค่า placeholder `000` ซึ่งไม่ใช่ชื่อวงจริง — โค้ดกรองทิ้ง
- slug ยาวไม่คงที่ (`6kv3m` = 5 ตัว, `vtps23` = 6 ตัว) — ห้าม hardcode ความยาว

และ **yaoi 14 รายการ** — ทุกรายการที่เข้าคลังผ่านการตรวจชื่อจริงเสมอ

หน้าเดียวมีรูปปกของเรื่องอื่นปนอยู่ด้วย โค้ดจึงเลือกกลุ่ม `id` ที่มีรูปมากที่สุด

### เลื่อนลงเพื่อโหลดต่อ (infinite scroll)

ไม่มีปุ่ม “หน้า 1/2/3” แล้ว — ผู้ใช้เลื่อนลงจนสุดขอบจอ ระบบต่อท้ายรายการให้เอง
- ตัวสังเกตคือ `#sentinel` + `IntersectionObserver` (`rootMargin: 600px`) ตรวจล่วงหน้า 600px ก่อนถึงปลาย
- ขยายทีละ `CHUNK` (12 รายการ) และโตเรื่อย ๆ ยิ่งเลื่อนเร็วยิ่งขยายมากขึ้น จนกว่าจะครบคลัง
- ค้นหา/กรอง/สลับมุมมองใหม่ → กลับไปแสดงจากต้นเสมอ (`resetScroll()`)
- ปลายคลังแสดง “— ครบทั้งคลังแล้ว —”

ตรวจแล้วจริงบนหน้าเว็บ: 12 → 22 การ์ด แล้วเปลี่ยนเป็น “ครบทั้งคลังแล้ว”

## สถาปัตยกรรม

```
index.html
assets/js/data.js      ตัวอย่างสำรอง (fallback) + สีแท็ก + ตัวเลือกเรียง
assets/js/sources.js    adapter ต่อแหล่งข้อมูล + parser
assets/js/app.js       UI, การกรอง, ตัวอ่าน
serve.js               static server + /api/proxy
```

### ทำไมต้องมี proxy

1. **CORS** — เบราว์เซอร์เรียกข้ามโดเมนไม่ได้
2. **Cloudflare บล็อก TLS ของ Node** — ทดสอบแล้วว่า `https.request` และ `fetch`
   ของ Node ได้ **403** จาก miku-doujin ไม่ว่าจะตั้ง header อะไร ส่วน `curl` ผ่านได้
   → proxy จึงใช้ `curl` เป็น fetcher
3. **ใส่ User-Agent แบบเบราว์เซอร์** — เว็บตอบ 403 ถ้าไม่มี

### ป้องกันการใช้ proxy ผิดทาง

| มาตรการ | ค่า |
|---|---|
| allowlist host | เฉพาะ `miku-doujin.com`, `doujin-th.com`, `netoruhentai.com`, `neko-hentai.net` อื่นตอบ 403 |
| scheme | รับเฉพาะ `https://` |
| rate limit | 40 คำขอ/นาที/host → เกินแล้วตอบ 429 |
| cache | 5 นาที ลดการยิงซ้ำ |

## การทำงาน

- **หน้าแรก** → ดึงรายการล่าสุดจาก `GET /` ของต้นทาง (ปอกจริง 24 รายการ ไม่ใช่ภาพจำลอง)
- **ค้นหา** → พิมพ์ในช่องบน → POST ไปที่ endpoint ค้นหาจริง (debounce 420ms) → เรนเดอร์ผลจริง
- **เปิดการ์ด** → ค่อยดึงรายละเอียด (ผู้วาด, ภาษา, จำนวนหน้า, แท็ก) — ทำแบบ lazy
- **กดอ่าน** → ดึง URL รูปทุกหน้า แล้วอ่านจากนั้น
- **รูปภาพ** → โหลดตรงจาก CDN ต้นทาง (`referrerpolicy="no-referrer"`) ไม่ได้ดาวน์โหลดเก็บ
- **ถ้าต้นทางล่ม** → ถอยไปใช้ข้อมูลตัวอย่างใน `data.js` และขึ้นแถบเตือนสีเหลือง
  ระบุชัดว่าปกที่เห็นเป็นภาพจำลอง ไม่ใช่ของจริง
- **ค้นแล้วไม่เจอจริง** → ขึ้นว่า "ต้นทางตอบกลับปกติ ผลลัพธ์ว่างจริง"
  ไม่ใช่อ้างว่าดึงไม่สำเร็จ (สองกรณีนี้คนละเรื่องกัน)
- **ตัวกรองด้านข้างไม่เดาค่า** → ฟิลด์ที่ต้นทางยังไม่บอก (ภาษา/หมวด/แนว ในหน้า listing)
  จะขึ้น "ต้นทางยังไม่บอก… — เปิดการ์ดเพื่อให้ดึงเพิ่ม" แทนการโชว์ค่าปลอม
  พอ hydrate แล้ว facet จะเติมค่าจริงเอง (`hydrate()` เรียก `buildSidebar()`)
  `SHAPE` ใน sources.js จึงต้องเป็นค่าว่าง — **ห้ามใส่ค่าเดา** เช่น `'doujinshi'`
- **เลือกหลายแหล่ง** → ใช้ `allSettled` เสมอ แหล่งหนึ่งล้มต้องไม่ทำให้อีกแหล่งหาย
  และข้อความต้องระบุเฉพาะแหล่งที่สำเร็จจริง

> รายการที่ได้จากการค้นหาสดจะ**ไม่ถูกกรองด้วยคำค้นซ้ำในเบราว์เซอร์**
> เพราะต้นทางกรองมาให้แล้ว และหน้า listing ไม่มีข้อมูลแท็ก — ถ้ากรองซ้ำรายการจะหายหมด

## เพิ่มแหล่งข้อมูลใหม่

1. เพิ่มรายการใน `SOURCES` และ `ALLOWED` ของ [serve.js](serve.js) / [sources.js](assets/js/sources.js)
2. เขียน adapter ที่มี `landing()` (รายการล่าสุด — ถ้าไม่มีจะถูกข้าม),
   `search()` และ `detail()` คืนค่าในรูปแบบมาตรฐาน
   (หรือผ่าน `SRC.normalize()` เพื่อเติมฟิลด์ที่ขาดให้ครบ)
3. id ต้องขึ้นต้นด้วยชื่อแหล่ง เช่น `mysite-xxxx` เพื่อให้ `hydrate()` หา adapter ถูก

ตรวจสอบ parser กับข้อมูลจริง (ครอบคลุมกฎ femboy + ทั้งสองแหล่ง):

```bash
node serve.js &            # ต้องรันเซิร์ฟเวอร์ไว้ก่อน
node check-parsers.js      # exit 0 = ผ่านทุกอย่าง
```

`check-parsers.js` จะ:
1. ทดสอบกฎ femboy 17 เคส (ต้องผ่านทั้งหมด — นี่คือ invariant หลักของแอป)
2. parse ผลค้นหาจริงจาก miku-doujin + ดึงรายละเอียดจริง 1 ชิ้น
3. เรียก netoruhentai จริง + เช็กว่าชื่อต้นฉบับที่ยืนยันจากหน้า detail ผ่านกฎ femboy/yaoi
